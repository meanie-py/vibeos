# Rust in the Kernel — ntkrnl-sys & Build Integration Reference

Deep reference for the kernel Rust workspace's FFI substrate and build wiring.
The short workspace overview, the Rust targets, the cross-platform pattern, the
load-bearing Key Rust/FFI Gotchas, and the cohabitation principle live in
`AGENTS.md` → "Rust in the Kernel".

## ntkrnl-sys — Kernel FFI Declarations Crate

Dual-layer FFI crate providing kernel type and function declarations for Rust kernel components:

```
sdk/lib/rust/ntkrnl-sys/
├── Cargo.toml
├── generate_bindings.sh       # Runs bindgen for all 3 architectures
├── postprocess_bindgen.py     # Post-processes raw bindgen output
├── verify_sizes.py            # Generates compile-time struct size assertions
└── src/
    ├── lib.rs                 # Re-exports both layers
    ├── base.rs                # Hand-written: NTSTATUS, PVOID, LIST_ENTRY, etc.
    ├── ke.rs                  # Hand-written: KSPIN_LOCK, KeAcquireSpinLock, etc.
    ├── mm.rs                  # Hand-written: POOL_HEADER, POOL_DESCRIPTOR, etc.
    ├── ex.rs, ps.rs, ob.rs    # Hand-written: pool constants, process, object
    ├── rtl.rs, interlocked.rs # Hand-written: RTL functions, interlocked ops
    ├── bindgen_common.rs      # Generated: shared helper types
    ├── bindgen_arm64.rs       # Generated: ~82K lines, ~3,300 extern functions
    ├── bindgen_amd64.rs       # Generated: ~83K lines, ~3,350 extern functions
    ├── bindgen_i386.rs        # Generated: ~81K lines, ~3,360 extern functions
    ├── size_check_arm64.rs    # Generated: 1,522 compile-time size assertions
    ├── size_check_amd64.rs    # Generated: 1,542 compile-time size assertions
    └── size_check_i386.rs     # Generated: 1,525 compile-time size assertions
```

**Layer 1 — Hand-written modules** (`ntkrnl_sys::base`, `ntkrnl_sys::ke`, etc.):
Curated declarations for the pool allocator and existing Rust kernel components.
Includes inline functions, macros, and convenience wrappers that bindgen can't
generate.

**Layer 2 — Bindgen kernel module** (`ntkrnl_sys::ddk::*`): Auto-generated from
the full `ntoskrnl.h` master header + `mm/ARM3/miarm.h` via bindgen. Covers ALL
internal kernel subsystems — MM (Mi*), OB (Ob*/Obp*), SE (Se*/Sep*), PS
(Ps*/Psp*), KE (Ke*/Ki*), IO (Io*/Iop*), EX (Ex*), CC (Cc*), CM (Cm*/Cmp*), LPC,
plus ~300 Nt* and ~190 Zw* syscalls. Provides ~3,300 extern functions, ~1,850
structs (including EPROCESS, ETHREAD, OBJECT_HEADER, MMPTE, MMPFN, MMVAD, TOKEN,
HANDLE_TABLE, POOL_HEADER), and ~4,400 type aliases with correct calling
conventions (including i386 fastcall/stdcall).

### Size Verification

~1,500 compile-time `const _: () = assert!(size_of::<T>() == N)` assertions per
arch verify every bindgen struct matches C layout. Generated by `verify_sizes.py`
which cross-compiles `sizeof()` expressions to LLVM IR via clang and extracts
values.

```bash
# Regenerate size assertions (after bindgen regeneration)
cd sdk/lib/rust/ntkrnl-sys
python3 verify_sizes.py

# Verify assertions are up to date
python3 verify_sizes.py --check
```

### Regenerating Bindings

```bash
# Prerequisites: cargo install bindgen-cli
cd sdk/lib/rust/ntkrnl-sys
bash generate_bindings.sh    # Regenerate bindgen output
python3 verify_sizes.py      # Regenerate size assertions
```

The script runs bindgen against `ntoskrnl.h` + `miarm.h` for all 3 targets
(`aarch64-pc-windows-gnu`, `x86_64-pc-windows-gnu`, `i686-pc-windows-gnu`), then
post-processes the output to extract shared helpers and add module headers. Key
wrapper header defines:
- `#define FORCEINLINE` — prevents inline function body expansion
- `#define _INTRIN_H_` — skips compiler intrinsics (not available in libclang)
- `#define __int64 long long` — type alias needed by various headers
- `#define __wfi()/__yield() ((void)0)` — ARM64 intrinsic stubs

**A generator that last ran before the upstream merge may not run at all.** win32k-sys's
broke four ways, all silently until someone needed a new type (the raw-input port,
2026-09-27): its flags came from a `main.c` compile rule that vanished when win32k went
Rust-only (it now reads the `win32k_residue` TUs); FreeType 2.10.4 deleted the
`internal/internal.h` its wrapper included; `vcruntime/intrin.h` now declares `__wfi`/`__yield`,
so the `#define __yield() ((void)0)` stubs break the arm64 parse; and bindgen ≥ 0.72 emits
`__BindgenOpaqueArray`, which the old postprocessor regex cut in half, leaving
`bindgen_common.rs` on a dangling attribute. The other islands carry the same wrapper lines
and will hit the last three on their next regen.

**Cast macros vanish.** bindgen emits no constant for `#define OBJID_CLIENT ((LONG)0xFFFFFFFC)`,
winuser.h's spelling since the merge, so a regen silently drops every `OBJID_*`.
`--clang-macro-fallback` fixes it and takes hours on the win32k header set (it reparses per
macro). win32k-sys instead dumps `clang -dM -E` beside each run, and
`postprocess_bindgen.recover_cast_macros` emits the integer-literal casts to integer
typedefs the island already has (38 per arch).

### Limitations

- **FORCEINLINE functions** (e.g., `KeGetCurrentIrql` on amd64) appear as extern declarations but have no exported symbol — must be hand-written or provided via overlay
- **Bindgen type naming** uses `_LIST_ENTRY` (with underscore prefix) vs hand-written `LIST_ENTRY` — the DDK module includes both via type aliases
- **Two skip types** in verify_sizes.py: `_GENERAL_LOOKASIDE_POOL` (complex union, bindgen disagrees with C) and `_LONGDOUBLE` (x87 long double, platform-specific padding)

## CMake Integration

The cmake-driven kernel build invokes `cargo build --release` for each Rust crate
that becomes a static lib, then links the resulting `.a` files into the
appropriate kernel-mode targets:

- `sdk/lib/rust/ntoskrnl-rust/` → `libkernel_rust.a` → linked into `ntoskrnl.exe`
- `sdk/lib/rust/hal-rust/` → `libhal_rust.a` (default) + `libhal_rust_mini.a` (`--features minihal`) → linked into HAL flavors and freeldr/mini_hal consumers
- `sdk/lib/rtl/` → invokes `cargo build` for `rtl-rust` and links into librtl

The cargo PoC (`sdk/lib/rust/ntoskrnl-cargo/`) is the long-term replacement for
the cmake-driven `ntoskrnl.exe` link. Today it reuses cmake-built `.obj` and `.a`
artifacts and just drives the final link from cargo; eventually it replaces the
cmake link entirely.

## Adding New Crates
1. Create directory under `sdk/lib/rust/`
2. Add to workspace `members` in `sdk/lib/rust/Cargo.toml`
3. Add `extern crate <name>;` in the appropriate umbrella crate's `lib.rs` (usually `kernel-rust/src/lib.rs`) — without this, cargo compiles the rlib but its `#[no_mangle]` symbols don't end up in `libkernel_rust.a` (memory `feedback_extern_crate_for_staticlib.md`)
4. Wire up `add_custom_command` + `target_link_libraries` in the appropriate cmake (typically `sdk/lib/rtl/CMakeLists.txt` for rtl-flavor crates, or the consumer module's CMakeLists)

## cmake→cargo cutover & cohab — recipes and traps

This section distills the reusable playbook for "turning off the lights on cmake":
making the main cmake build drive a PE module's **final link** from cargo (the
`sdk/lib/rust/<crate>` reactos-link manifest) instead of `add_library`/
`add_executable`, and for compiling the module's remaining C/asm residue
in-cargo rather than reusing cmake-built `.a` files. It applies to kernel DLLs
(kdcom/bootvid), device drivers (`.sys`), the freeldr loaders (uefildr/rosload),
and the user-mode spine binaries (smss/csrss/services/winlogon/winsrv).

### Deciding when a HYBRID TU can leave CMake — measure, don't estimate

A hybrid TU is one whose class is already Rust but whose `.cpp` is still compiled, because
something else in the link still calls into it. Its remaining cost is **not** its line count.
`rustconv hybrid-closure <tu> --arch i386` reports it as a set intersection over the real link
inputs:

```
retained = defined(this TU's .obj)  ∩  undefined(everything else linked)
```

Measured this way, `folders/CFSFolder.cpp` read as 2,283 lines of work and was 21 symbols; the
nine remaining shell32 Wave-1 hybrids are 11,119 lines and **67 symbols between them**.

Two things the by-hand version of this kept getting wrong, both now structural in the tool:

- **The Rust archive belongs on the undefined side.** A `#[no_mangle]` body that calls back into
  a C++ helper is exactly the edge keeping the `.cpp` alive, so leaving `lib<target>_rust.a` out
  understates the closure.
- **The link unit is wider than one CMake target.** shell32 pulls in shellmenu, shelldesktop and
  shellrecyclebin as static libs, each with its own `*.dir`. Scoping consumers to a single `.dir`
  reads as "free to leave" right up until the link fails — it hid a live consumer of
  `CRecycleBin.cpp` and could not see `shellmenu/CMergedFolder.cpp` at all.

Output is classified by how each symbol can be re-published from Rust, which is the actual work:
`extern_c` takes a `#[no_mangle]` directly; `cxx_free` needs `EXTERN_C` on its header declaration
first; `cxx_member` has **no** `EXTERN_C` spelling — one name, one class scope — so it needs an
inline forwarder in the class body calling an already-published C bridge (see `CFSFolder.h`).

### The `add_cargo_module` helper

`add_cargo_module(<target> <crate> <output> [KIND
kerneldll|kernelexe|kernelmodedriver|win32dll|win32exe|efi|native]
[BODY_CRATE <rust-staticlib>] [BODY_CRATES …] [EXTRA_DEPENDS …] [NO_CD]
[DESTINATION] [NAME_ON_CD])` lives in `sdk/cmake/gcc.cmake`.
`add_cargo_kernel_dll` is a thin
`KIND=kerneldll` wrapper. It runs `cargo build --release --target <target> -p <crate>
--bin <bin>` (WORKING_DIRECTORY `sdk/lib/rust`, output at
`sdk/lib/rust/target/<stem>/release/<bin>.exe`), then
does KIND-specific post-link: **kerneldll** = `native-pefixup --kerneldll` (+ i386
`fix_lld_forwarding.py`); **kernelexe** = `native-pefixup --kernel` (+ i386 fwd
fix) [ntoskrnl/ntkrnlmp]; **kernelmodedriver** = `native-pefixup
--kernelmodedriver` (+ i386 fwd fix) [win32k.sys]; **efi** = strip `.rossym` +
`--strip-all`; **native** = none. `<bin>` = crate name minus the `-cargo` suffix.

**ARCH → target** (since 2026-07-12, stable-toolchain Axis B — see `build-system.md`
§"Cargo target model"): **amd64** → `x86_64-pc-windows-gnu`, **arm64** →
`aarch64-pc-windows-gnullvm` — the BUILTIN triples on pinned **stable**, precompiled std,
**no `-Z build-std`**, plus `RUSTFLAGS=-C force-frame-pointers=yes` (and amd64-only
`-C link-self-contained=no`). **i386** → `<crate>/i686-kernel.json` + pinned nightly +
`-Z build-std=core,alloc,compiler_builtins -Z build-std-features=compiler-builtins-mem`;
it is the last build-std cell (needs `rustc-abi: x86-softfloat`) and retires with wow64.
The `<stem>` (cargo's `target/<stem>/` subdir) is the target triple, or `i686-kernel` on i386.

win32k.sys (the largest module after ntoskrnl) is the kernelmodedriver
template: `ModuleKind::KernelDll` already equals the kernelmodedriver link-flag
set; the Rust body (`win32k-kernel-rust`) builds with `.rust_user_target()` +
i386 `.rust_build_rustflags("-C target-feature=-sse,-sse2")` (the proven cmake
custom_command config, NOT the softfloat kernel json); the 21-file C residue
(+ i386 dib/floatobj asm) stays cmake-compiled as `add_library(win32k_residue
STATIC)` and is reused via `static_libs` placed FIRST in the group, preserving
the C-before-Rust cohab first-match order the old objects-then-archives link
had. The version resource is a checked-in per-arch
`win32k-cargo/data/win32k-<arch>.rc.res` regenerated by
`tools/gen_win32k_res.py` (`--check` verifies byte-parity).

Numbered traps a cutover must handle:

1. **Keep `spec2def(<dll> <spec> ADD_IMPORTLIB)` in cmake** for any exporting
   module. The importlib it produces is `lib<basename>` and is *independent* of
   the module target — consumers (`add_importlibs(ntoskrnl … kdcom)`) link the
   importlib, not the module, so removing `add_library` is safe **as long as
   spec2def stays**. The cargo link makes its own `.def` for the dll's exports
   internally. (Drivers and uefildr export nothing → no spec2def. rosload's
   freeldr import lib is instead self-hosted via reactos-link
   `.import_lib("…/freeldr.spec","freeldr.sys","freeldr")`.)
2. **`add_cd_file` FILE-form does NOT auto-wire the CD-target dependency** (only
   the TARGET form does, via `if(_CD_TARGET)`). After an `add_cd_file(FILE …)`,
   manually `add_dependencies(bootcd/livecd/bootcdregtest <target>)`. Safe
   because `boot/` is processed before `drivers/` and LIVECD_FILE_LIST
   consumption is deferred. For a `$<TARGET_FILE:…>` that a `custom_target` lacks
   (cargo modules are custom_targets, no TARGET_FILE), pass an explicit path +
   keep `DEPENDS <target>`; `add_cd_file` then needs BOTH `TARGET` (dep) and
   `FILE` (path).
3. **`GLOB_RECURSE` the bin crate + reactos-link + BODY_CRATE for DEPENDS.** A
   cargo link is opaque to cmake; an incomplete DEPENDS lets a stale output mask
   a source fix — cmake won't re-run the custom_command if the output exists and
   DEPENDS are unchanged. **EXTRA_DEPENDS must list the .a/.obj FILE PATHS, not
   just the producing custom-TARGET names**: a custom_command's DEPENDS on a
   custom-target is *order-only* (no content tracking), so editing a path-dep
   crate would relink against a stale archive (e.g. `ninja uefildr` said "no work
   to do" with a newer `libfreeldr_rust.a`). DEPENDS on the OUTPUT file paths
   (which ninja content-tracks) closes this. Reactos-link layer-2 complements it
   by emitting `cargo:rerun-if-changed` per static_lib and per watched src dir.
4. **Per-arch entry + image base.** Entry symbol: `___ImageBase` on i386 (cdecl
   triple-`_`), `__ImageBase` on amd64/arm64. Image base: `0x10000` on
   i386/amd64, **`0x7FFB00000000` on arm64**. (For drivers/kerneldll the entry is
   `DriverEntry@8` — see below.)
5. **Nightly + build-std is a hard requirement** for these modules (custom kernel
   json). The legacy stable `i686-pc-windows-gnu` cmake path built without
   build-std; the cargo path uses nightly build-std like every reactos-link
   cargo-drive.
6. **`vibeos-cli build --clean` does NOT cold the cargo link.** It nukes
   `build-<arch>/rust-*-target`, but the cargo link writes to
   `sdk/lib/rust/target/` (workspace, outside the build dir). True cold = `rm` the
   output binary(ies) **and** `rm -rf sdk/lib/rust/target/<stem>`, then ninja —
   verify "Compiling compiler_builtins/core/alloc" appears.

### Device drivers — kernelmodedriver = KernelDll

A kernelmodedriver `.sys` IS a `ModuleKind::KernelDll`: PE entry `DriverEntry@8`
(i386 `_DriverEntry@8`, amd64/arm64 undecorated `DriverEntry` — write
`#[no_mangle] extern "system" fn DriverEntry` and it decorates naturally),
exports nothing (`--exclude-all-symbols` is already in KernelDll), image base =
kerneldll base. **No spec2def** (drivers have no exports). Recipe:
`add_cargo_module(<t> <t>-cargo <t>.sys KIND kerneldll BODY_CRATE <t>-rust
DESTINATION reactos/system32/drivers [EXTRA_DEPENDS …] [NO_CD])`. The version
`.rc` is dropped; `add_registry_inf(…)` stays in cmake (independent of the link).
Softfloat `i686-kernel.json` is correct for kernel drivers (no float crosses the
ntoskrnl FFI boundary — contrast user-mode DLLs which need the standard target).

Driver FFI playbook (per-arch export resolution is the gauntlet — verify against
the real binary):

- **Oracle: `llvm-objdump -p <old cmake .sys>`** shows exactly which symbols the C
  driver imported per-arch — ground truth for "exported here vs FORCEINLINE here".
- **FORCEINLINE-not-exported, per-arch.** Many DDK "functions" are FORCEINLINE
  (no symbol) on some arches and real exports on others:
  - `ExInitializeFastMutex` — FORCEINLINE everywhere → use
    `ntkrnl_sys::inline::ex::…` (init-only, safe to inline).
  - `ExAcquireFastMutex`/`ExReleaseFastMutex` — amd64/arm64 export them stdcall
    (`extern "system"`); i386 exports the **fastcall `Exi*`** variants
    (`#[cfg(x86)] extern "fastcall" { #[link_name="ExiAcquireFastMutex"] … }`).
    Do NOT call the kernel-internal `inline::ex::_ExAcquireFastMutex` from a
    driver — its i386 slow path references `KiAcquireFastMutex@4`, not exported.
  - **IRQL** — i386/arm64 export stdcall 2-arg `KeRaiseIrql`/`KeLowerIrql` from
    HAL; amd64 has them FORCEINLINE (IRQL==CR8) so the C imports NO IRQL symbol →
    inline the CR8 read/write on amd64 (`mov {},cr8` / `mov cr8,{}`). Roll your
    own per-arch; do not lean on `inline::tier1`/`KeRaiseIrqlInternal` (those
    extern a kernel-internal `KeRaiseIrql` that's undefined for drivers).
- **Callback/fn-ptr slots** (MajorFunction PDRIVER_DISPATCH, FastIo, DriverUnload,
  DRIVER_CANCEL) are per-arch bindgen `Option<extern "stdcall" fn>` (i386) vs
  `Option<extern "C" fn>` (amd64/arm64). Assign an `extern "system"` fn item via a
  size-checked `Some(core::mem::transmute(Fn as *const ()))` — ABI-identical per
  arch, only the Rust *type string* differs (a plain `Some(..)`/`as` is a type
  error across arches).
- **`CONTAINING_RECORD`** → pointer math: `(entry as *mut u8).sub(offset_of!(_IRP,
  Tail))`. Use `core::mem::offset_of!`, and reach `static mut` globals via
  `addr_of!`/`addr_of_mut!` (nightly build-std denies `static_mut_refs`);
  `MaybeUninit::zeroed()` for a const-init zero global struct.
- **Dead-residue trick (skip `c_from_compile_db`).** If the only C left is
  pure-data (e.g. a `guid.c` of `initguid.h` GUID definitions) and the Rust body
  self-provides those symbols (e.g. defines the GUID as a `pub static` used via
  `addr_of!`), the C symbol is unreferenced → DROP the `.c` entirely (no OBJECT
  lib, no compile_db). Always check whether the Rust body self-provides the
  residue's symbols first.
- A "duplicate symbol" line in a driver build log is usually a *warning* from the
  concurrent ntoskrnl link (`--allow-multiple-definition` is on for all
  KernelDll). The real driver error is `could not compile <crate>` lower down →
  build the `-rust` crate directly (`cargo build --target <arch>-kernel.json -Z
  build-std=… -p <crate>`) to see it cleanly.

### Shared rlib — one C file in N binaries → one Rust rlib

When a single C file is compiled into multiple binaries (e.g.
`ntoskrnl/config/cmboot.c` → ntoskrnl + uefildr + rosload), do NOT re-translate
per consumer. Extract the existing translation into a standalone **rlib** (NOT a
staticlib) that every consumer links via `extern crate`:

- The crate is a plain `rlib`, `#![no_std]`, **no `panic_handler`** (the final
  artifact's umbrella provides it); dep `ntkrnl-sys default-features=false`.
- **Decouple from the origin crate's internals.** Route private-macro calls
  through self-contained equivalents (adapting-for-sharing is allowed, it is not a
  revert); turn `use crate::…` of context globals into `extern "C"` imports the
  consumer supplies. **Context-local symbols live in the consumer**, not the
  shared crate — the kernel supplies them from its own modules, the loaders from a
  new shims file; the shared crate only *imports* them.
- Cohab: comment the `.c` out of every consumer's source list; add the crate as a
  workspace member + a dep in each consumer's Cargo.toml + the umbrella.
- **DORMANT TRANSLATION (false "100%" accounting)** — a `.rs` can be fully
  translated, committed, AND wired into `mod.rs`, yet never actually link, because
  the corresponding `.c` is *still compiled* (uncommented in CMakeLists). Direct
  `.c.obj` files are handed to the link before the archive, so they satisfy
  `DllMain`/`MoveFile*`/etc., and lld — which pulls archive (`.a`) members only on
  demand — never extracts the `.rs`'s members. The Rust is dead weight; the C runs.
  Being in `mod.rs` is **NOT** proof of integration. This is what made `dllmain.c`
  + `move.c` quietly survive the kernel32 "literally-100% Rust body" milestone
  (`6a4adf940d7`); flipped in `3336d15e603`. Detect: for each `pub mod X;` in a
  crate's `mod.rs`, grep CMakeLists for an *uncommented* `X.c` — a match = dormant.
  Flipping it then often surfaces (a) globals the `.rs` left mangled (need
  `#[no_mangle]` so cross-TU `extern` importers resolve) and (b) `#ifdef`-arch
  paths the translation dropped — both invisible while dormant.
- **Removing a file from a crate repartitions its cgu=256** — an intra-crate call
  rustc used to inline now goes through a symbol, which can surface a latent ABI
  decl mismatch (e.g. an `extern "C"` decl of a stdcall `_..@8` export). Fix the
  decl, don't revert.
- **`ar` NEVER PRUNES on source removal** — after commenting a `.c` out of a cmake
  `.a`, the stale `.obj` lingers in the archive, and a force-included `.obj` in a
  build.rs reused-objects list *shadows* archive members → the link silently keeps
  running stale C. After a cohab flip you MUST `rm` the stale `.a` and scrub the
  build.rs reused-objects, then `nm libX.a | grep <flipped-symbol>` to prove it's
  gone. (This class of false-green is also why loader changes must be hash-verified
  in the actual boot media, especially under `--allow-stale`.)

### reactos-link engine primitives

Builders on `Linker` (`reactos-link/src/lib.rs`) that the cutovers added/use:

- **`rust_user_target()`** — force the `rust_staticlib` main body onto the
  STANDARD user target (`i686`/`x86_64-pc-windows-gnu`, `aarch64-gnullvm`, stable,
  no build-std) even for a kernel-ish module. NEEDED for the freeldr loaders: the
  *link* uses the kernel json (x86-softfloat ABI) but the body must build
  standard-target like cmake did, or the float ABI diverges. (Phase-2 user-mode
  cargo builds must also use the standard target, never the softfloat kernel json.)
- **`rust_build_rustflags(s)`** — RUSTFLAGS for the main-body build. **i386
  `-C target-feature=-sse,-sse2` must be stated EXPLICITLY**: `build_rust_crate`'s
  `kernel=false` path runs from the build dir (cwd ≠ workspace), so the workspace
  `.cargo/config.toml [target.i686-pc-windows-gnu]` `-sse,-sse2` is NOT discovered.
  Any standard-target i386 leaf (cnt-rust-lib, cport-rust, hal-mini) must re-state
  it. (rustflags discipline across agents: kernel-target crates go in
  ntoskrnl-cargo's `crt_rustflags` match in the `kernel=true` branch; user-target
  crates in the `rustflags`/cnt else-if of the `kernel=false` branch — different
  branches auto-merge.)
- **`rust_watch(&[dirs])`** — emits `rerun-if-changed` for each built crate's src
  dir + Cargo.toml, including PATH-DEPS in other workspace crates. Closes the
  stale-`.a` class (cargo would otherwise skip rebuilding the body and link a
  stale archive).
- **`c_from_compile_db(cmake_target, &[c_sources])`** — compile a module's deep-C
  residue IN-cargo by replaying cmake's `compile_commands.json` clang invocation
  (flag-exact by construction), instead of reusing a cmake-built `.a` via
  `static_libs()` (which needs `ninja <lib>` first). Requires
  `CMAKE_EXPORT_COMPILE_COMMANDS ON` (configure-time only, no build). It strips the
  ninja-built `.pch` quad but keeps the configure-time `cmake_pch.h` force-include;
  redirects `-o` to OUT_DIR; runs with `cwd = entry.directory`. Disambiguate a
  `.c` compiled into multiple targets by the `CMakeFiles/<target>.dir` marker, so
  `cmake_target` must be the real cmake target name. **C-ONLY**: a cmake lib that
  is C+asm in one archive (`add_asm_files` + `add_library`) splits into TWO
  in-cargo archives — `c_from_compile_db("name", C)` in the C-archive group
  position (BEFORE the Rust archives, preserving C-first dup-symbol ordering) +
  **`asm_archive("name_asm", asm)`** in the post-static_libs position. Safe only if
  the asm symbols can't shadow an earlier static_lib's. **GUARD empty asm**
  (e.g. arm64 has none): `if !asm.is_empty()` — an empty `asm_archive` panics
  "produced no objects". Get the EXACT per-arch source list from
  `build-<arch>/compile_commands.json` (filter `CMakeFiles/<target>.dir`), not the
  cmake transcription (skip `cmake_pch.h.c`). asm that has no `#ifdef` doesn't care
  about the AsmDefineSet; raw `.S`/lowercase `.s` with `#include` works because the
  asm path forces `-x assembler-with-cpp`. (`c_shim_flags()` and
  `asm_include_dirs()` are sibling primitives for per-shim codegen flags, e.g.
  freeldr's `-mno-sse`, and a minimal `-I` set for assembling a raw `.S`.)

### Cargo C-residue shave — what to delete vs flip

Once the link is cargo-driven, eliminate the `c_from_compile_db` C-compile leaks
(each replays cmake's flag-exact clang with the full `-I` tree = a transitive
cmake dependency). Two residue classes:

1. **Vestigial cohabitation stubs** (`*_rust_stub.c` — pure-comment, 0-symbol
   TUs). Their only purpose was the cmake-era `add_executable()` "needs ≥1 TU to
   force Rust-archive extraction" hack. With `add_cargo_module` the cargo link
   pulls the Rust body archive directly via the CRT's symbol refs (e.g. libnt's
   `_NtProcessStartup` → `main`), so the stub is DEAD → just delete it from the
   cargo `c_from_compile_db` list and relink to prove. (Never delete the `.c`
   from disk — philosophy. Just stop compiling it.) Correspondingly, an **OBJECT
   lib that exists ONLY to seed `compile_commands.json`** (`add_library(… OBJECT
   *_rust_stub.c)`) is removable from cmake **iff no cargo build.rs still names it**
   in `c_from_compile_db` / `resource_from_rc` — keep ones that still feed a `.rc`
   resource compile.
2. **Provider shims** (real intrinsic/macro/COM glue — interlocked,
   `CONTAINING_RECORD`, `InitializeObjectAttributes`, COM-vtbl dispatchers) → flip
   to Rust. Reproduce the EXACT per-arch target symbol set by `nm`-ing the
   cmake-built `*_shim.c.obj` on each arch and matching it 1:1 via natural ABI
   decoration (i386 `extern "system"` → `_Name@N`, `extern "C"` → `_Name`;
   amd64/arm64 undecorated). Interlocked via `&*(p as *const AtomicI32)` →
   `fetch_add/sub` (returns NEW, so `.wrapping_±1`) / `swap` (returns OLD); COM
   dispatch via `*(*(p as *const *const *const c_void)).add(idx)` then transmute to
   the method fn-ptr.

**Dup-`#[no_mangle]`-across-ABIs trap:** Rust rejects two `#[no_mangle]` of the
SAME identifier even across different ABIs / cfg-modules (it dedups on the Rust
identifier BEFORE platform decoration) → "symbol `_X` is already defined". A C
shim that defined both a cdecl and a stdcall twin of one name can't become two
no_mangle fns. FIX: unify on ONE symbol (e.g. the stdcall `_X@N`) and switch the
lone other-ABI caller's `extern "C"` decl to `extern "system"` (same op; only the
stack-cleanup convention changes, and caller+callee just must agree).

## Cohab link-resolution trap catalog

A crate compiling with 0 errors ×3 arches is **necessary but not sufficient** for a cohab flip. The cohab *link* resolves the translated `.rs` against the surviving C objects, the module `.spec`/`.def`, and sibling modules (win32k, imm32, etc.) — a whole class of cross-TU issues the compiler cannot see because the other half lives outside the crate. **i386 is the strictest linker (decorated `_Name@N`): do the i386 cohab link first and iterate it to zero undefined symbols before handing to the ×3 gate.** The recurring traps:

- **Spec FORWARDERS are not linkable internal symbols.** A `.spec` line `@ stdcall Foo(..) NtUserFoo` is resolved at *export* time by the `.def`; there is **no callable `_Foo@N`** inside the DLL. A translated body that calls `Foo(...)` via `extern "system" { fn Foo; }` → `undefined symbol _Foo@N`. **Fix:** route through the runtime target (the syscall/inline wrapper), not a direct extern. *Classify a name:* `grep "stdcall NAME" module.spec` — a trailing forward target (`… NtUserNAME`) ⇒ forwarder ⇒ wrap; no target ⇒ real own-export ⇒ keep the extern.
- **Cross-TU DATA exports the still-C side reads by address.** If surviving C reads `&SOME_struct` from a TU you translated, the Rust file must define a `#[no_mangle] pub static SOME_struct: T` with the **exact C layout**, and any embedded function pointers `transmute`d to the C fn-ptr type (calling-convention-identical per arch). rustconv routinely **drops** these statics — re-add from the C. *Always grep the C consumer for the **active** (non-`#if 0`) reference* before assuming a symbol is cross-TU; a `#if 0`/comment-only reference means the Rust static stays a plain `pub static` (no `#[no_mangle]`).
- **Runtime dispatch tables are not imports.** A `FN(name)` macro that expands to `gApiTable.pName` is a global function-pointer table filled at runtime by a *sibling* module — the DLL does **not** import the target library. A direct `extern "system" { fn Name; }` → undefined. **Fix:** mirror the table struct layout (field order up to the highest slot used; unused slots = pointer pads), `extern "C" { static gApiTable; }`, and inline wrappers that call through it.
- **cdecl C helpers wrongly given stdcall.** A plain-cdecl C helper (`_name`, no `@N`) declared `extern "system"` asks the i386 linker for `_name@N` → undefined. **Fix:** `extern "C"`. (amd64/arm64 hide this — cdecl and stdcall are the same undecorated symbol there; only i386 catches the mismatch.)
- **Inline/`__inline` header helpers have no exported symbol.** A `strsafe.h`-style `__inline` (e.g. `RtlStringCchCopyNW`) is not a real export — reimplement locally.
- **MSVC intrinsics have no extern symbol on amd64/arm64.** `InterlockedExchange` and the `_Interlocked*` / `_byteswap*` / `_BitScan*` family are inline intrinsics on amd64/arm64 (only i386 ships the CRT stdcall export). A direct extern **links on i386, fails amd64/arm64**. **Fix:** `core::sync::atomic::Atomic*` (e.g. `AtomicI32::swap`). Scan each wave for these before the gate — **i386-green does NOT imply amd64-green.** (`memcpy`/`memset`/`strlen` are fine — compiler-rt provides them on all arches.)
- **UNICODE macros vs the decorated generic export (i386).** `winuser.h`-style macros map `SetWindowLongPtrW`→`SetWindowLongW`, and generic `GetWindowLong`/`SendMessage`→the `…W` export. The generic decorated form has no symbol on i386 — cfg-split to the `…W` variant / a forwarder.

**Takeaway:** the four "invisible on amd64/arm64, fatal on i386" classes (forwarders, cdecl-vs-stdcall, MSVC intrinsics, UNICODE macros) mean **i386 is the canary** — link it first, drive undefined-symbol count to zero, *then* scan explicitly for the intrinsic trap (which i386 hides) before the cross-arch gate.

- **The `-cargo` main.rs panic handler is the LIVE one — a loud handler in the
  staticlib is dead code.** With `--allow-multiple-definition`, lld resolves
  `rust_begin_unwind` to the **first** definition on the link line, and the bin
  crate's object precedes every archive — so the empty-shell `main.rs` handler
  always wins over `libX_rust.a`'s. Several main.rs comments used to claim the
  opposite ("the staticlib's handler wins first-match") — that lore was
  backwards, proven 2026-07-06: freeldr-rust's loud PL011/debugcon panic
  handler was gc'd dead in `uefildr.efi` on all 3 arches
  (`strings uefildr.efi | grep FREELDR-RUST-PANIC` → 0 hits) while the bare
  `loop {}` stub in `uefildr-cargo/src/main.rs` was live. **Rule: put the loud
  panic handler in the `-cargo` main.rs, not (only) the rlib/staticlib.** The
  2026-07-06 sweep did this for all 38 cargo mains (32 DbgPrint, uefildr/
  rosload raw-UART, 4 kd-transports deliberately bare — DbgPrint from inside
  the KD transport would recurse into the broken transport).

## HAL ABI contract (hal.spec)

`hal/hal.spec` is **the** contract for anything importing from `hal.dll` (PnP/ACPI/video drivers, ntoskrnl). It must stay stable across the whole translation window — C and Rust both link against the same decorated export set.

**Export surface:** 102 exports — **76 stdcall, 25 fastcall, 1 extern (data)**. Roughly half are untagged (all arches); the rest carry `-arch=` annotations (largest cohorts: `i386,arm,arm64` and `i386,x86_64`), so a symbol's very *existence* is per-arch — check the `.spec` `-arch=` tag before declaring an extern for it.

**Internal surface:** ~144 `Halp*` declarations in `include/halp.h`. The cohab pattern requires each signature — calling convention, return type, parameter layout — to stay byte-identical between the surviving C and the incoming Rust, or the two halves silently disagree (per-arch ABI mismatches were real bugs).

**Declaration rule (match the C header verbatim):**

| C symbol kind | Rust `extern` ABI |
|---|---|
| NTAPI (`stdcall`) | `extern "system"` |
| FASTCALL | `extern "fastcall"` |
| pure cdecl | bare `extern "C"` |

`extern "system"` resolves per-arch (i386 NTAPI = stdcall `_Name@N`; amd64/arm64 NTAPI = cdecl undecorated), so it is the correct default for NTAPI — but FASTCALL and cdecl must be spelled explicitly; do not blanket everything as `extern "system"`.

**Verify before the flip:** `nm` the cargo/staticlib archive against the `.spec`-expected decoration. A mismatch links fine on amd64/arm64 and breaks i386.

**The `.S` / NT-ABI boundary is not translatable residue.** The shared HAL asm (`systimer.S`, `trap.S`, `pic.S`, `apictrap.S`, `tsccal.S`) `#include`s `ks{386,amd64}.inc`, which `geninc` generates from the NT ABI headers — i.e. it depends on **NT struct field-offset definitions**, the *same* layout `ntkrnl-sys` bindgen mirrors into Rust. Porting the asm to `global_asm!` would not sever that dependency (Rust asm still needs the offsets via `offset_of!`). Treat this asm as the ABI boundary Rust consumes independently, not as C left to translate.

**Per-arch KIRQL/CR8 gotcha (cohab class):** an IRQL constant hardcoded to the i386 value (`HIGH_LEVEL = 31`) writes a reserved bit via `mov cr8, 0x1F` on amd64 (KIRQL maps to CR8, 4 valid bits) → #GP, which exception dispatch mis-attributes to whatever function is running (looked like an MM BUGCHECK 0x1E). Any HAL constant touching CR8/IRQL must be per-arch (31 i386 / 15 amd64).

## The kernel↔user boundary (ntdll)

ntdll is unique among cohab targets: it is the **user-mode half of a kernel contract**. The kernel side is already Rust and smoke-green — translating ntdll's body must **not renegotiate the contract**. Three things are special.

**1. Must-not-drift exports (kernel binds them by name).** At `PspMapSystemDll` the kernel resolves four ntdll exports from the `.spec` and stores their addresses in `KeUser*Dispatcher` / `PspSystemDllEntryPoint`. Their exact `.spec` decoration and ABI are **load-bearing** — a decoration drift silently mis-binds: `KiUserExceptionDispatcher`, `KiUserApcDispatcher`, `KiUserCallbackDispatcher`, `LdrInitializeThunk` (the first user instruction in every new thread). `nm` the cargo-built archive against the `.spec`-expected decoration **before** the cohab flip lands. (Same load-bearing-export class as the FreeLDR `PeLdr*` set.)

**2. The trap trampolines stay asm (and carry non-upstream patches).** `dispatch/{i386,amd64,arm64}/dispatch.S` — the kernel→user trampolines — use ml64 SEH unwind pseudo-ops and exact kernel-built stack contracts that `global_asm!` can't cleanly express. **They stay asm by design.** Syscall stubs (`NtXxx`/`ZwXxx`) are spec2def-generated, not translated — ntdll-rust calls them as `extern "system"` FFI. **Critically — preserve the DUMMY_PSEH safety-net blocks bit-for-bit:** the i386/amd64 `dispatch.S` carry hand-added `#ifdef _USE_DUMMY_PSEH` blocks **not in upstream ReactOS** (the user-mode mirror of the kernel-side DUMMY_PSEH swallow — swallow continuable software exceptions via `ZwContinue`; pass hardware/noncontinuable to 2nd-chance via `ZwRaiseException`; skip the int3 byte on `STATUS_BREAKPOINT`). Because DUMMY_PSEH is always on for our build, the checked-in `.s` must include these blocks **unconditionally** — flag them so they aren't "cleaned up" as cruft.

**3. Bootstrap hazard (dual-mode).** `LdrInitializeThunk`/`LdrpInit`/`LdrpInitializeProcess` run as the **first user instruction in every thread**, fabricated by the kernel as a fake user APC — i.e. they execute *before the process has its own runtime*. Translated bootstrap code cannot assume TLS, heap, or loader state is up yet; keep it allocation-free and self-contained the same way the C did.

**Rule of thumb:** ntdll's PE *body* is fair game for translation, but the **contract surface** (the 4 named exports, the asm trampolines + their DUMMY_PSEH blocks, the spec2def syscall stubs) is fixed — translate around it, never through it.

## RPC-server DLL cohabitation (widl `_s.c` → Rust stub)

Pattern for flipping a **widl-generated RPC server DLL** (a `.idl` → `<iface>_s.c` marshalling stub plus a set of `#[no_mangle] extern "system"` server methods) from C to Rust. This is a **shipping, battle-tested** shape in this tree — it already drives **svcctl** (services.exe) and **winreg** (winlogon). Mirror those, don't invent.

### The three-crate shape (per RPC module)

| Crate | Kind | Role |
|---|---|---|
| **`<mod>-sys`** | rlib (bindgen) | The marshalled wire types. Bindgen `build-*/dll/win32/<mod>/<iface>_s.h` per-arch (allowlist the wire-type prefix), mirroring `sdk/lib/rust/lsass-sys/`. |
| **`<iface>-stub`** | staticlib | The generated Rust RPC server stub that **replaces** `<iface>_s.c`. Its `build.rs` calls `reactos_link::generate_rpc_stub_rust("<idl>", "<iface>_s", "<c-target>")`. Deps `midl-rt`. Mirror `sdk/lib/rust/svcctl-stub/`. |
| **`<mod>-rust`** | staticlib | The translated method bodies: `#[no_mangle] pub unsafe extern "system" fn FooXxx(...)` + `*_HANDLE_rundown` context-rundowns + `MIDL_user_allocate`/`MIDL_user_free`. Mirror `sdk/lib/rust/services-rust/src/rpcserver.rs`. |

`tools/widl_to_rust.py` transliterates the widl `<iface>_s.c` → `.rs` against the `sdk/lib/rust/midl-rt/` substrate (ABI-asserted `repr(C)` mirrors of `MIDL_STUB_DESC`/`MIDL_SERVER_INFO`/`RPC_SERVER_INTERFACE`/`RPC_DISPATCH_TABLE`). `generate_rpc_stub_rust` reads the **compiled `_s.c.obj`** via `llvm-nm` to recover exact per-arch symbol decorations — this is what solves the i386 `@N` decoration problem automatically.

**Cohab flip:** comment the translated `.c` bodies out of `dll/win32/<mod>/CMakeLists.txt`, **drop `${CMAKE_CURRENT_BINARY_DIR}/<iface>_s.c`** from the sources, link the three Rust staticlibs.

### Non-obvious gotchas (all cost real debug time)

- **This tree uses widl, not MS-MIDL.** `sdk/cmake/widl-support.cmake` `add_rpc_files` is the active generator; `midl-support.cmake` is dead. **Replace** the emitted `_s.c` with the Rust stub — do NOT keep it as compiled C.
- **`MIDL_user_allocate`/`MIDL_user_free` ABI:** C names them lowercase, but `rpcndr.h` `#define`s lowercase→UPPERCASE. A Rust `#[no_mangle]` gets no macro expansion, so define + call the UPPERCASE names with `extern "system"` (`__RPC_USER` = stdcall, i386 `@4`).
- **`*_HANDLE_rundown`** context-rundowns must exist (`extern "system"`, i386 `@4`) or the stub table won't link.
- **`@ stub` spec entries** are genuinely-unimplemented — translate-as-stub returning `STATUS_NOT_IMPLEMENTED`; correct `_Name@N` on i386 via `#[no_mangle]` (never `#[export_name]`, which double-decorates).
- **Link is the oracle for cross-file exports.** rustconv occasionally emits a cross-file C function as a *private* Rust fn (no `#[no_mangle]`) → undefined symbol at DLL link. A stale DLL can falsely boot green — always confirm `ninja <mod>` rc=0 **and** `undefined symbol` count 0 ×3. Fix: restore `#[no_mangle] pub extern "C"`.
- **The lone DUMMY_PSEH site.** These modules typically have exactly one `_SEH2_EXCEPT` that validates a caller handle and **mutates an output in the except body** → must become dead code under `USE_DUMMY_PSEH`; validate the pointer/signature in safe Rust *before* the deref, never rely on the catch.

**Reference files:** `tools/widl_to_rust.py` · `sdk/lib/rust/midl-rt/src/lib.rs` · `sdk/lib/rust/svcctl-stub/build.rs` · `sdk/lib/rust/services-rust/src/rpcserver.rs` · `sdk/lib/rust/reactos-link/src/lib.rs` (`generate_rpc_stub_rust`) · `sdk/cmake/widl-support.cmake`.

### Differential-fuzz parity harness (`rtl-difftest` pattern)

For the pure byte-math pieces of a translated module (SD/ACL/SID packing, RID arithmetic, array pack/unpack, bitfield encode) you can **prove bit-for-bit equivalence** vs the genuine compiled C — strictly better than C-anchoring, because it hits the translation goal *with* an oracle. Host crates (`cargo test`, **no QEMU**), `publish=false`, workspace members. Copy from `sdk/lib/rust/rtl-difftest/`.

The 4 load-bearing tricks: (1) `build.rs` writes a wrapper TU: `#define Foo ref_Foo` for each public symbol, then `#include "<repo>/…/genuine.c"` verbatim → genuine & Rust coexist as `ref_Foo` vs `cabi::Foo`. (2) `cc::Build` with **`.cargo_metadata(false)` + emit each object as `cargo:rustc-link-arg=<obj>`** — a build-script `rustc-link-lib` does NOT reach integration tests; link-args do. (3) **Force widths in a minimal `refstub/`:** `typedef unsigned short WCHAR;` and `typedef int NTSTATUS;` (host `wchar_t` is 32-bit, host `long` is 64-bit). (4) **Minimal `refstub/`** replaces the genuine header chain; `scrape_protos()` (copy verbatim) auto-emits forward prototypes. `tests/diff.rs`: `extern "C" { fn ref_*(...) }`, an xorshift RNG, per-iter call both + `assert_eq!` on the return, every out-param, and the whole dest buffer. **Reference:** `sdk/lib/rust/rtl-difftest/{build.rs,tests/diff.rs,refstub/}` · `sdk/lib/rust/cnt-difftest/`.

## cmake → cargo LINK cutover (spine binaries)

Recipe for moving an **already-Rust-bodied but cmake-LINKED** binary (`add_executable`/`add_library` + `target_link_libraries` the Rust `.a` with `--allow-multiple-definition`) to a **cargo-driven link** via the shared `reactos-link` engine — mirroring `ntoskrnl-cargo` / `ntdll-cargo`. Validated across smss/csrss/csrsrv/winsrv/basesrv + lsass/winlogon/userinit/services.

**Pick the right ModuleKind:**
- **`Win32Exe { entry, subsystem }`** — user-mode win32 exe (lsass, userinit, winlogon, services). `--subsystem,windows:5.01` (GUI) or `console:5.01`, `--gc-sections`, no `-shared`. User-mode ⇒ `kernel_rust=false` (build the *standard* user rust target).
- **`NativeExe`** — native-subsystem exe (smss, csrss): `native:5.01`, `_NtProcessStartup@4`/`NtProcessStartup` entry, per-arch explicit image base. Needs `.rust_user_target()`. On arm64 add `.stack_reserve(2MB)` — llvm-dlltool collapses delay-imports so deep `LdrpLoadDll` overflows the 1MB default.
- **`Win32Dll { entry, image_base }`** with subsystem `native:5.01`/`console:5.01` — spine DLLs (csrsrv native; winsrv/basesrv console). `_DllMain@12`/`DllMain`, no `--gc-sections`.

The float ABI of the empty cargo bin **shell** is irrelevant — only the body `.a`'s float ABI matters.

**EXTRA_DEPENDS must be `.a` FILE PATHS, not cmake target names** whenever the producer lives in a directory configured *after* the consumer (`base/` configures before `dll/`, so a `base/`-module can't see a `dll/`-importlib *target* name — a file path edges order-independently). OBJECT-lib residue/resource targets already in scope (`<m>_c`, `<m>_res`) can be passed by target name.

**Resource `.res`: windres-replay via `resource_from_rc`.** For a binary with a load-bearing `.res` (MANIFEST/dialogs/bitmaps/STRINGTABLEs — check the `.rc`; pure version info is omittable), compile it in-cargo with `Linker::resource_from_rc(rc_rel, res_target)`: it replays cmake's flag-exact `windres` command from `compile_commands.json` (positional in/out, NO `-o`; `current_dir = build-<arch>`). Keep a resource-only OBJECT lib alive so the windres entry stays in `compile_commands.json`.

**Entry-point decoration depends on the UNICODE keyword** (read `set_module_type`): win32gui + UNICODE → `wWinMain` → entry `_wWinMainCRTStartup` (i386); win32gui WITHOUT UNICODE → `WinMain` (`_WinMain@16`) → `_WinMainCRTStartup`. Wrong entry → undefined `_wWinMain@16`/`_WinMain@16` at link.

**Trap: arch-gated shim + reused C `.a` = silent stale link.** A cohab-flip shim gated `#if defined(__i386__)` combined with a reused C archive makes amd64/arm64 silently link *stale C*. Fix: `ninja -t clean <lib> && ninja <lib>` to prune the archive and expose the gap; add the missing `#else` branch. (`vibeos-cli build --clean` is RUST-only, so it can't re-archive C.) Once the residue moves to `c_from_compile_db`, staleness is moot — cargo recompiles the shim fresh every link.

**Engine note:** spec2def `-a` takes **`x86_64`** for amd64, NOT `amd64` (an unknown token silently falls back to i386 `@N` decoration). Reference: `sdk/lib/rust/reactos-link/src/lib.rs`, `ntdll-cargo/build.rs`, `ntoskrnl-cargo/build.rs`.

## Translating a standalone kernel `.sys` driver

Translating a whole standalone driver (kbdclass, i8042prt, classpnp, cdrom, cdfs, arm64vid, framebuf, pci) is a different job from swapping one `.c` inside an existing DLL: the driver's types come from headers the shared `ntkrnl-sys` bindgen never sees, and an LLM pass leaves thousands of mechanical compile errors that collapse to ~15 systemic roots. This section is the front-to-back workflow for the **body crate** — get it to compile clean ×3 arches — which then feeds the cohab link (`### Device drivers — kernelmodedriver = KernelDll` and the trap catalog above).

### Where every driver symbol comes from — the three substrate layers

| Tier | What it is | Where it lives |
|---|---|---|
| **Kernel-internal** | `NTSTATUS`, `IRP`, `DEVICE_OBJECT`, `Io*`/`Ke*`/`Rtl*` fns | shared `ntkrnl-sys` (`base`, `ke`, `mm`, `ex`, `ob`, `rtl`, giant `ddk` bindgen) |
| **Ordinary driver DDK** | `DO_*`, `IRP_MJ_*`, `FILE_DEVICE_*`, `RTL_REGISTRY_*`, `IoCompleteRequest`, `CONNECT_DATA`, `ctl_code()` | shared `ntkrnl-sys/src/driver_ddk.rs` |
| **This driver's private headers** | `CLASS_DEVICE_EXTENSION`, `FUNCTIONAL_DEVICE_EXTENSION`, `TRANSFER_PACKET`, FCB/VCB/CCB, its `IOCTL_*` values | per-driver `types_*.rs` (bindgen'd) + a hand `<drv>_h.rs` |

**The DDK tier is a real gap you must not re-shim per driver.** `ntkrnl-sys` bindgen runs over `ntoskrnl.h` (the *kernel-internal* master header), not `wdm.h`/`ntddk.h`, so plain-driver consts and FORCEINLINE helpers never land in `ntkrnl_sys::ddk`. That surface is hand-maintained in `sdk/lib/rust/ntkrnl-sys/src/driver_ddk.rs` (~250 lines: `DO_*`/`FILE_DEVICE_*`/`IRP_MJ_*`/`IRP_MN_*`/`RTL_REGISTRY_*` consts, `CONNECT_DATA`, a `const fn ctl_code(dev,func,method,access)`, enum re-exports, and macro/FORCEINLINE wrappers `IoCompleteRequest`→`IofCompleteRequest`, `IoCallDriver`→`IofCallDriver`). Two constraints:

- **It must stay disjoint from `constants.rs`.** A driver globbing both hits E0659 on any overlap (`IRP_MJ_*`, `IO_*_INCREMENT` already in `constants.rs`). Compute the real overlap with a script and omit those from `driver_ddk.rs`; don't trust the doc comment.
- **Both `constants.rs` and `driver_ddk.rs` must be in `config.HAND_WRITTEN_MODULES`** (`tools/rustconv/rustconv/config.py`) or the resolver's catalog never scans them and flags every DDK symbol unresolved. This one change dropped kbdclass's unresolved count 87→37, free, via `rustconv resolve`.

Const values are **header-authoritative** — pull from `sdk/include/xdk/iotypes.h`, `rtlfuncs.h`, `ntbasedef.h`, `psdk/ntstatus.h`; never hand-guess a DDK/IOCTL value.

### Private bindgen — `gen_driver_types.sh`

The driver's own structs live in its private headers, not the shared bindgen. An LLM stubs them with `_dummy: [u8; 256]` placeholders — names compile, every field access fails (this regressed classpnp to 2000+ errors). Generate exact layouts with `tools/rustconv/gen_driver_types.sh <driver>` → `types_{i386,amd64,arm64}.rs` + a `#[path]`-dispatched `types.rs` (override with `OUT_CRATE_DIR=…`). The recipe it encodes, per driver:

- **`ALLOW_FILES`** (`--allowlist-file '.*classp\.h'`) bounds emission to types defined in the driver's own headers.
- **Blocklist every kernel type name** the shared bindgen already exports (grep `pub (struct|enum|type|union)` from `bindgen_<arch>.rs`) so kernel types keep a single identity. Each `types_<arch>.rs` does a **private** `use ntkrnl_sys::ddk::*;` to resolve blocklisted field types inside its structs — never `pub use` (re-exporting `ddk` collides E0659 with the modules' `driver_ddk::*` globs).
- **Version + arch defines MUST match the driver's CMakeLists** — wrong NTDDI version emits/drops version-gated fields and shifts every offset:

  | Driver | `_WIN32_WINNT` / `NTDDI_VERSION` |
  |---|---|
  | classpnp | `0x602` / `0x06020000` (Win8) |
  | cdrom | `0x603` / `0x06030000` (Win8.1) |
  | cdfs | `0x502` / `0x05020400` default |

  Arch defines (msvctarget.h needs `_M_*`): **i386:** `-D_M_IX86 -D__i386__ -D_X86_`; **amd64:** `-D_WIN64 -D_M_AMD64 -D__x86_64__ -D_AMD64_`; **arm64:** `-D_WIN64 -D_M_ARM64 -D__aarch64__ -D__arm64__ -D_ARM64_`. Add `-I build-<arch>/sdk/include/reactos/mc` for generated `bugcodes.h` (arm64).

- **`WRAPPER_INC` (not just `ALLOW_FILES`) must `#include` every header whose types you need.** The allowlist only *filters* parsed types — it can't emit a type the include graph never reaches (classpnp's `classp.h` doesn't transitively include `wmistr.h`/`ntddstor.h`, so `WNODE_*`/`STORAGE_*` were absent until added). Verify by the **typedef** name (`WNODE_ALL_DATA`), not the `_`-tag.
- **`UNBLOCK` un-opaques a kernel struct the driver reaches into.** Some ddk types are opaque (`{ _address: u8 }`) so field access resolves to nothing (`_SCSI_REQUEST_BLOCK`). List them in `UNBLOCK="…"` → removed from the blocklist so the driver's own bindgen (which includes `scsi.h`/`srb.h`) emits the full struct into `types_*.rs`; then strip those names from the module's `ddk::{…}` imports so they re-point to `crate::types`. Expect a net partial each pass.

**Grind guard: the compile-repair grind must NEVER edit `types_*.rs`** — those are the generated exact layouts; re-stubbing a struct there is the exact regression this tool prevents. Only fix imports/signatures/field-access in the *module* `.rs` files.

### Consuming-crate import recipe (the `arm64input` template)

Glob the small, mutually-disjoint hand modules; keep the giant bindgen `ddk` **selective**:

```rust
use ntkrnl_sys::{globals::*, constants::*, base::*, ke::*, mm::*, rtl::*, ex::*, ob::*};
use ntkrnl_sys::driver_ddk::*;
use ntkrnl_sys::ddk::{ /* ONLY ddk-unique names */
    PDEVICE_OBJECT, PIRP, PIO_STACK_LOCATION,        // pointer aliases (NOT in base)
    _UNICODE_STRING, _OBJECT_ATTRIBUTES, _GUID,       // bindgen `_`-structs
    _EVENT_TYPE_NotificationEvent,                    // bare enum consts, VERBATIM
};
```

- **Globbing `ddk::*` is fatal** — redefines every scalar (`NTSTATUS`/`ULONG`) `base` already provides → 100+ E0659. Always selective for `ddk`.
- **Type identity matters.** A device-extension `UNICODE_STRING` field must be `ddk::_UNICODE_STRING` (not `base::UNICODE_STRING`) or every Rtl/Io call mismatches. `base` has no `KSPIN_LOCK` (it's `ddk` = `ULONG_PTR`).
- **`ex::ExAllocatePoolWithTag` is a `<const N>` const-generic helper, not the 3-arg DDK runtime fn** — a driver calling `ExAllocatePoolWithTag(pool,size,tag)` gets E0747. Import it from `ddk` to shadow the `ex::*` glob.
- The driver's private-header types (device extensions, `IOCTL_*` via `driver_ddk::ctl_code`, pool tags, GUIDs) go in a hand `<drv>_h.rs` that globs `base::*` and selective-imports only the `ddk` types it embeds.

### Grinding the systemic compile errors

Thousands of rustc errors reduce to ~15 roots. **Don't grind per-site.** Dispatch parallel read-only investigator subagents (one per rustc error family, analyze-and-propose-a-deterministic-patch), then apply the deterministic fixers under `tools/rustconv/`:

| Fixer / action | Clears |
|---|---|
| `fix_type_casts.py` | E0308 width/sign (from the primary span's **`label`**, not `children`), `*mut↔*const`, fn-ABI mismatch |
| `resolve_imports.py` | E0425/E0422/E0408 missing-imports — `_GUID{…}` literals, match-arm consts (an unimported const silently becomes a catch-all binding — a real bug) |
| `harvest_consts.py` | E0425 undefined consts — add the driver's *private* header dir to `HEADER_DIRS`; `sizeof`/`FIELD_OFFSET` → `size_of`/`offset_of!` |
| `fix_field_paths.py` | E0609 — `c2rust_unnamed`→`__bindgen_anon_N`, `ptr.Field`→`(*ptr).Field`, nested anon/union BFS |
| `fix_bitfield_methods.py` | E0615 — bindgen bitfield `.X` read→`.X()`, `.X = v`→`.set_X(v)` |

(Fixers live at `tools/rustconv/fix_*.py` and `tools/rustconv/{harvest_consts,resolve_imports}.py`.) Singular roots to fix by hand:

- **Fabricated `NT_SUCCESS`/`NT_ASSERT` locals** with inconsistent sigs across files — delete, `use ntkrnl_sys::base::NT_SUCCESS`.
- **ABI transmute target inference (the amd64/arm64 fix).** i386 repair bridges NTAPI-callback ABI with `transmute::<extern "system" fn, extern "stdcall" fn>(F)` — correct on i386 but hardcodes stdcall, breaking amd64 (NTAPI=cdecl). Drop the explicit target: `transmute::<SRC, _>(F)` lets rustc infer the arch-correct target from the bindgen field type. Keep the explicit `SRC` (forces fn-item→fn-ptr coercion; bare `transmute(F)` fails E0591).
- **Dead version-gated code → `#[cfg(any())]`, don't delete.** A driver built at NTDDI_WIN8 compiles out its `#if (NTDDI_VERSION >= NTDDI_WINTHRESHOLD)` fns but the LLM translated them → references to types that only exist higher. Gate the whole Rust fn with `#[cfg(any())]` (always-false, preserves source, mirrors the C `#if`).

**Parallel per-file agents finish it.** After deterministic tooling plateaus, dispatch N subagents each owning a **disjoint** set of module `.rs` files, fixing rustc errors against the C ground truth (rule: *don't fabricate a kernel-API/macro signature — report it*). Fix the shared substrate centrally first; give each agent a private `CARGO_TARGET_DIR=/tmp/<name>`.

### ⚠️ Cold `CARGO_TARGET_DIR` — the driver-crate false-green

**`cargo check` in the default/warm target dir silently reuses stale per-crate artifacts and reports 0 errors on broken code** — especially after adding a module. An entire "classpnp compile-clean ×3" history was a warm false-green; a cold check exposed ~8 i386 + 83 amd64 + 101 arm64 errors. Rules: (1) every verification that matters uses a fresh per-arch `CARGO_TARGET_DIR=/tmp/fresh-<arch> cargo check -p <crate> --target <t>` — never trust a warm 0 (the cargo analogue of the smoke harness's stale-media refusal). (2) Don't run the per-arch cascade on ONE arch and trust it — `fix_type_casts` writes arch-specific casts (`as u64`) that break other arches on *shared* files; prefer `as _` over `as u64`/`as ULONG_PTR`.

### bindgen blind spot: macro-spliced struct fields

Distinct from an opaque `{ _address: u8 }` stub — here bindgen emits a **plausible-looking partial** struct. When a C struct pulls leading fields via a *layout macro*, bindgen parses only fields textually *after* the macro; the spliced fields vanish and the emitted `size_of` assertion is **self-consistent but wrong vs C** (it checks the Rust struct against bindgen's own mis-parse, not a C oracle, so it passes):

```c
typedef struct _PCI_COMMON_CONFIG {
    PCI_COMMON_HEADER_LAYOUT      // 64-byte macro
    UCHAR DeviceSpecific[192];
} PCI_COMMON_CONFIG;              // real C sizeof = 256
```
→ bindgen emits `{ DeviceSpecific: [UCHAR; 192] }` and asserts `== 192`. **Heuristic:** a driver-private struct suspiciously small / field-less *and* whose C uses a `*_LAYOUT`/`*_HEADER` macro — assume dropped fields, size-check pass notwithstanding. **Fix locally in the crate** (don't wait on a bindgen regen): define the correct layout with the real header type, then overlay-read it, and shadow the broken `ddk` type by placing `use crate::shared::PCI_COMMON_CONFIG;` *after* the `use ntkrnl_sys::ddk::*;` glob.

### Standalone cohab crate (staticlib template)

For a driver built as its own `.sys` (vs a `.c`-in-DLL swap), the lightweight mechanism — proven on `arm64vid.sys`, template `sdk/lib/rust/arm64input-rust/` — is a **staticlib crate + a placeholder C stub**, independent of `add_cargo_module`:

- New crate `<drv>-rust/`, `crate-type = ["staticlib"]`. Dep `ntkrnl-sys` (or `win32k-sys` for a GDI display driver — and *only* win32k-sys; a second direct ntkrnl-sys path builds it twice → E0432). Own `#[panic_handler]` + `rust_eh_personality` stub. Add to workspace `members`; no `extern crate` in the umbrella needed.
- Cohab CMake mirrors `arm64input/CMakeLists.txt`: cargo-build custom command → copy `.a`; `add_library(<drv> MODULE rust_cohab_stub.c)`; comment `.c` sources `# replaced by Rust`; `target_link_libraries`. `rust_cohab_stub.c` is a one-liner `typedef int <drv>_cohab_placeholder;` (a MODULE needs ≥1 source). Keep the `.c` on disk.
- **Per-arch `RUST_TARGET`** — select per-arch like `hal/halx86/CMakeLists.txt` (i386 `+ -C target-feature=-sse,-sse2`); don't arch-gate the crate.

### Compile-clean ≠ complete — verify export & runtime coverage

A driver crate can `cargo check` clean with a large fraction of exports **extern-stubbed rather than defined** — invisible until the cohab link fails with N undefined exports (classpnp compiled clean with 32 of 60 exports as unbodied `extern`, ~6,200 C LOC never translated). Before claiming done: **count `#[no_mangle]` definitions against the module `.spec`**; verify against **serial, not the smoke number** (arm64vid linked + booted "green" while BUGCHECK-0xB4'ing); confirm the `.sys` mtime is fresh + `nm` shows hundreds of Rust symbols. Watch for **tree-sitter truncation on huge C files** (rustconv hard-truncates at the first unparseable PSEH2 block — class.c stopped at ~line 3,800) — `#include`-back-split the `.c` before translating the tail.
