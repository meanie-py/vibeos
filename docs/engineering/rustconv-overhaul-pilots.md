# rustconv overhaul and retained pilots

The pilots replace SysAudio `pin.c` and PortCls `resource.cpp` in their actual driver
builds: 977 source lines including comments. The original sources remain on disk as
oracles. All eight SysAudio functions and the complete PortCls resource-list object
remain enabled in Rust.

## Guarded defaults

Paid C translation enables fact/call/wide sealing and requires a compiler anchor for
every selected function. The owning CMake target's profile audit runs before payment;
its errors block the run. Independent textual C inventory checks the plan, and Rust
syntax-tree inventory checks definitions after final assembly/postprocessing. Comments,
foreign declarations and macro token trees cannot satisfy a missing definition.

These are presence and bounded consistency checks, not a proof of equivalent behavior.
Direct sealed constant arguments are checked against their source call positions;
arbitrary expressions and control-flow equivalence still require review/tests.

Changed paid cache namespaces/bodies refuse an implicit repurchase. `--replay-only`
never falls through to the API. Legacy paid batch/submit entry points require the
explicit `--unsafe-unprotected` opt-out. Five obsolete cache/paid repair scripts moved
to `tools/rustconv/archive/`; active specialized tools and their tests remain.

The pilots also exposed and fixed parser loss through nested SAL annotations,
standalone assembly-import annotations, diagnostic-statement deletion, variadic/fixed
ABI mixing, IRP inline import selection, and byte-vs-int comparison narrowing during
compile repair. The latter must use C integer promotions: resource type `-1` must not
be truncated to descriptor byte `255`.

## PortCls ownership boundary

`resource_owner.rs` is generated by the bounded single-interface
`CUnknownImpl<IResourceList>` backend. Rust owns allocation, interface storage, vtable,
constructor state, sequentially consistent atomic AddRef/Release and destruction.
It uses the SDK-derived vtable types on all three architectures; it does not reproduce
the hidden C++ object layout. Unsupported extra bases, state types, constructors or
base/destructor logic are refused.

The eight paid method bodies use a context containing pointers into the Rust owner.
QueryInterface, the two factories and the allocator/interface adapters are translated
Rust in `resource_support.rs` and `resource_factory.rs`. Allocation order, the stored
outer-unknown pointer, failure status/output behavior and tagged versus untagged frees
follow the source. No compiler-owned C++ object or runtime adapter is linked for this
class. The remaining unrelated PortCls classes still compile as C++.

Generate/review the ownership scaffold with the worktree's Python environment:

```sh
export PYTHONPATH="$PWD/tools/rustconv${PYTHONPATH:+:$PYTHONPATH}"
python -m rustconv cpp-com drivers/wdm/audio/backpln/portcls/resource.cpp \
  --class CResourceList --kernel-owned \
  --kernel-base drivers/wdm/audio/backpln/portcls/private.hpp \
  --kernel-bridge drivers/wdm/audio/backpln/portcls/resource_rust_bridge.h \
  -o ~/vibeos-rust-staging/portcls-owner-review.rs
```

The sibling reference C/header/C++ bridge and provenance manifest must first exist;
this command compiles both oracle sides on all three targets before emission.
Its explicit Rust hooks must compile and receive behavioral verification before a
new class is activated. Scaffold generation alone is not a completed translation.

## Evidence and limits

- `sysaudio-difftest`: 710 buffer/status/allocation comparisons of the genuine C
  `GetConnectRequest` against the shipping Rust function.
- `portcls-difftest`: 1,080 scenarios against genuine `resource.cpp`, covering both
  factories, each allocation failure, empty/invalid lists, QI identity and failure,
  reference counts, descriptor types including -1/255/256/511, virtual calls,
  AddEntry/parent insertion and buffer contents. Eight concurrent threads also perform
  80,000 AddRef/Release pairs on each implementation before checking final destruction.
- The host C++ fixture uses GCC at O1 with `-fcheck-new` and
  `-fno-aggressive-loop-optimizations`: its nullable pool allocator and trailing `[1]`
  arrays must retain their kernel-source meaning. Default aggressive host compilation
  invalidated that oracle. The matching host fixture layouts test behavior, not NT ABI.
  Shipping bindings and driver links are checked separately on all three NT targets.
- Run both suites with `./vibeos-cli difftest --only portcls-difftest,sysaudio-difftest`.
  This does not establish complete audio-device or streaming behavior in QEMU.

The compiler survey samples six explicit TUs over three architectures; it is not a
statistical estimate for the whole OS. Run `python -m rustconv.anchor_survey` with
source paths and `--output report.json`. The retained report is
`rustconv-anchor-survey.json` beside this document. Raw source names, parser misses,
compiler refusals and anchored names are recorded separately. Fourteen runs cover
every inventoried body; two more complete but omit `CdSetFileObject` (i386/amd64),
and two i386 runs crash in c2rust. Compiler success alone is therefore insufficient.
The paid pipeline requires each selected body to have an anchor and refuses both
missing bodies and compiler crashes by default.

Paid banks in this worktree are `.responses/20260912-212443-pin.c` and
`.responses/20260912-221905-resource_rust_reference.c` under `tools/rustconv/`.
They contain roughly $0.23 of model work. Both have been replayed without new API
calls. PortCls's initially empty preamble response was recovered by deterministic
source-derived assertion macros, preserving all eight already-paid workers.
