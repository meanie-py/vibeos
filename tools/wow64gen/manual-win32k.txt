# wow64gen deep-marshal list for the WIN32K table (NtGdi*/NtUser*, ordered by
# win32ss/w32ksvc32.h; guest EAX carries 0x1000+index). Same rules as
# manual.txt: one name per line, # comments; a listed name becomes a loud
# WOW64_NEEDS_MANUAL stub routed to Wow64ManualDispatch (wow64_manual.c).
#
# GDI/USER structs are mostly pointer-free and identical 32/64 (RECT, POINT,
# SIZE, COLORREF, LOGBRUSH sans hooks...), so auto zero-extension covers far
# more of this table than the ntdll one. List here the calls whose args embed
# POINTERS or ULONG_PTR fields (UNICODE_STRING, DEVMODEW+driver extra,
# LOGFONT arrays with pointers, MSG with ULONG_PTR wParam...).
#
# Bring-up policy: intentionally MINIMAL — every unlisted call with a
# divergent struct will misbehave loudly under the per-syscall trace; add it
# here + a marshaller when boot coverage hits it.

# The LARGE_STRING family. LARGE_STRING is 12 bytes on i386 and 16 on the host
# (PVOID Buffer at +8), so auto-thunking one hands win32k a wild 64-bit pointer
# that it dereferences under the USER lock — a whole-desktop wedge, not a clean
# fault. NtUserCreateWindowEx (above) was listed in M8; NtUserDefSetText was
# missed, and every stock window hits it via DefWindowProcW(WM_NCCREATE) setting
# the title from CREATESTRUCT.lpszName. These two are the entire family — if a
# new win32k syscall ever takes a PLARGE_STRING, it belongs here.
NtUserDefSetText

# M16 (task #43): NtUserMessageCall(FNID_DEFWINDOWPROC, WM_WINDOWPOSCHANG*) carries
# a WINDOWPOS by lParam. The guest passes a 28-byte 32-bit WINDOWPOS; 64-bit win32k
# reads it as 40 bytes -> field shift past the two leading handles -> garbage
# cx/cy/flags, so DefWindowProc's WINDOWPOSCHANGING size adjustment corrupts the
# window (collapses to 0x0, no WM_PAINT). The manual thunk marshals the lParam
# payload 32<->64 for this (FNID,Msg); every other message flat-passes as before.
NtUserMessageCall

# NtUserInitializeClientPfnArrays — INTERCEPT, not a marshaller. The guest's
# PFNCLIENT/PFNCLIENTWORKER are arrays of function pointers (4 bytes guest, 8
# host), and win32k copies them into the GLOBAL gpsi callback table, not per
# process — so a guest reaching that body is read at host width AND corrupts
# callbacks for native 64-bit processes. Harmless today only because win32k
# early-outs on ClientPfnInit and native user32 always initializes first; that
# is ordering, not a guarantee. wow64_manual.c returns SUCCESS without calling
# the kernel, which is exactly what the early-out already produced.
NtUserInitializeClientPfnArrays

# NtUserSendInput — E22, the size-as-an-ARGUMENT member of the cbSize class.
# marshalgen's WowAmSizeIn/Out rewrites a leading `cbSize` FIELD; SendInput
# states its element size in arg 2, which no struct diff can associate with
# arg 1, so this one is hand-written. INPUT is 28 bytes in the guest and 40 on
# the host (the union is 4-aligned vs 8-aligned, and each arm's dwExtraInfo
# widens), and win32k rejects `cbSize != sizeof(INPUT)` outright — so every
# SendInput from every 32-bit process silently did nothing.
NtUserSendInput

# NtUserThunkedMenuInfo — E22, and a trap worth stating: the PROTOTYPE says
# LPCMENUINFO but win32k casts it to PROSMENUINFO and reads `cbSize` bytes out
# of the caller, accepting anything in [sizeof(MENUINFO), sizeof(ROSMENUINFO)].
# So the payload is a CALLER-DECLARED VARIABLE SIZE, and a generated marshaller
# sized from the MENUINFO layout diff would have the kernel read past the end
# of its own 40-byte bounce buffer for any caller that declared more. Only the
# MENUINFO size class is marshalled here; anything larger goes to the kernel on
# the guest's own pointer, exactly as before, and the kernel decides.
NtUserThunkedMenuInfo

# Window/class procs crossing into the kernel (wow64_pfnmap.c). win32k keeps
# the 64-bit user32's apfnClientA/W as the system procs and picks an ANSI
# window's A proc by comparing against them. So a guest system proc must be
# swapped for the host's in the same slot going in, and a host proc coming back
# must be swapped for the guest's, or the guest calls a truncated 64-bit
# address. GWL_WNDPROC/GCL_WNDPROC go through the *Ptr entry points, since the
# 32-bit ones narrow the value and an unmapped high half cannot be recovered.
# Unlisted, the flat thunk returned the host's ButtonWndProcW narrowed to
# 0xb2057640, and user32:class executed it.
NtUserSetWindowLong
NtUserSetClassLong
NtUserGetCPD

NtUserBuildPropList
