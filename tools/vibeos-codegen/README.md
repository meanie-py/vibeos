# Native code generators

`tools/codegen` builds and runs the standalone, pinned-stable Rust binary. Generation
also lives in a library: the linter's committed-header drift check calls it directly.
The former Python entry points delegate to this binary; they contain no generation logic.

```sh
tools/codegen --list
tools/codegen --all --check          # compare all 11 outputs, without writing
tools/codegen apisets-table          # regenerate one recipe
tools/codegen bugcodes-h --stdout    # generated bytes only
tools/codegen error-tables --input path/to/error.c --output tables.rs
tools/codegen ntoskrnl-res --arch amd64 --check
tools/codegen ntdll-res --arch i386,amd64,arm64 --module ntdll,ntdll_vista --check
tools/codegen committed-res --arch arm64 --jobs-json
```

`--all` selects the eleven text outputs. Resource commands require `--arch` explicitly
and the corresponding local build inputs. Exit status is 0 for success, 1 for stale/missing output in check mode, and 2 for
invalid arguments, input errors, or failed generation. Source overrides extract
the supplied input literally; default recipes use this checkout's declared inputs.
`--root` selects a checkout; relative `--input`, `--output`, and `--header` paths
are relative to the caller. `nls` has three outputs and does not support `--stdout`
or a single output override. `msvcrt-errlist --output` requires an existing marked
Rust file and preserves the code outside its generated block.

All recipes render successfully before writes start. Each changed output is replaced
atomically; unchanged files keep their timestamps. This is not a transaction across
multiple files: an I/O error can leave earlier outputs updated. Output symlinks are
rejected. Generated provenance comments retain the old script names for byte parity;
the compatibility entry points keep their regeneration instructions working.

The default RTL recipe preserves the shipping `STATUS_NOT_SAME_OBJECT` extension
from `9495f2330ac` and the illegal-instruction provenance comment from `501abe55d05`.

insertion points are checked; changes require reviewing the override. `--all` renders
the constants from the newly generated tables, before either file is written.

The original winerror generator rejected its current table input's own `ERROR_TABLE`
identifier as an unresolved SDK constant. The native extractor excludes that dispatch
identifier. Existing value resolution and header precedence are preserved.

During migration, the eleven rendered outputs were compared byte-for-byte against
the Python implementations at `e8821e62376`: 1,023,731 bytes total, including the
CRT block rather than its surrounding module. For literal RTL parity the explicit
source override was used; the default recipe additionally preserves the shipping
divergences above. Winerror parity used the table-value region, excluding the
dispatch identifier that broke the old script. Checks exposed two pre-existing
freshness differences: a missing `DRIVER_POWER_STATE_FAILURE` constant and the
placement of `STATUS_ILLEGAL_INSTRUCTION`; the generated copies now match.

`vibeos-cli check-tooling` runs the Rust fixtures and CLI integration suite, including
freshness of all eleven outputs. Lint bootstrap fingerprints this library's sources
and included text templates as well as the lint crate itself.

## Resource generation

The five resource generators are also native: `hal-res`, `ntdll-res`, `ntoskrnl-res`,
`win32k-res`, and `committed-res`. Their former `gen_*_res.py` entry points delegate
to the binary. Legacy architecture defaults remain in those entry points for existing
callers; the native commands always require an explicit architecture. The legacy
committed-resource helper retains its caller-relative checkout lookup.

`resource_specs.json` preserves the Python recipes' ordered include/define tables;
the common language list and kernel architecture tables are shared. Thirteen fixed
module/architecture commands and binary outputs were compared with Python at
`9fa2caf4741`. The ordered command vectors have frozen SHA-256 oracles in
`tests/resource_commands.json`, normalized only by replacing the checkout and temporary
work directory with `{ROOT}` and `{WORK}`. CLI fixtures also exercise binary output,
message-sidecar staging, compiler failures, empty/missing output, and multi-job failure
before any destination changes. No committed resource blobs were regenerated.

`committed-res` replays compile-database recipes and also accepts their `arguments`
form. Its read-only `--jobs-json` format retains the old `jobs` / `messages` schema
(including `null` for an absent database). Ordinary generation requires all four cell
recipes for each selected architecture; missing inputs fail instead of claiming success
after skipping them. Fixed-resource `--jobs-json` uses `{WORK}` placeholders and performs
no compilation. `--stdout` and `--output` require exactly one selected binary output.

Both native generation and the linter's drift replay always map canonical `/tmp/vibeos`
paths to this checkout, even when that directory exists. They reject working/source
paths that resolve outside the checkout, and fixed-resource compilation rejects foreign
generated include directories and message sidecars. Compiler tools may still be shared.
The existing drift check retains its optional-artifact SKIP classifications; explicitly
requested generation fails on missing or incomplete inputs.

## Binding and header generation

Seven more commands replace the corresponding Python implementations:

| Command | Inputs/options | Output |
| --- | --- | --- |
| `com-macros` | `--bindgen FILE [--only IFoo,IBar] --output FILE` | COM vtable call helpers |
| `enum-consts` | `HEADER TAG [--by-member] [--only A,B] [--type u32]` | computed Rust constants on stdout |
| `ioctl-consts` | `HEADER [--prefix IOCTL_FAMILY_] [--type u32]` | SDK-resolved macro constants on stdout |
| `ks386-inc` | local i386 generated headers | committed i386 assembly constants |
| `ref-protos` | `file.c` and its local amd64 object | CRT reference prototypes and rename exclusions |
| `rpc-guards` | `--header FILE [--prelude HEADER] --out-c FILE --out-h FILE` | SEH wrappers for WIDL stubs |
| `delaylib` | `--def FILE --arch ARCH --out FILE [--clang TOOL] [--ar TOOL]` | compiled delay-import archive |

These commands require explicit selection; `--all` still covers only the eleven text
outputs. `enum-consts` and `ioctl-consts` accept `--check RSFILE`, comparing the constants
present in that Rust file. Mismatches, unparseable values, and zero overlapping constants
fail. Relative input/check paths for these two commands retain their checkout-relative
meaning. Headers retain replacement decoding for legacy non-UTF-8 comments. Other paths
are caller-relative. `--output` selects a text destination; `ref-protos --output-dir DIR`
redirects both outputs to an existing directory. The latter requires a built local
amd64 CRT object and fails if `llvm-nm` fails or finds no functions.

`com-macros --bindgen - --parse-json` exposes the native parser through stdin/stdout.
The Python `parse_vtbls` API used by rustconv is a thin bridge retaining its tuple shapes.
`rpc-guards` retains both client and `s_` prototypes, matching the original implementation.
`delaylib --stdout` renders assembly without compiling. Archive compilation happens in a
private temporary directory, then replaces the destination atomically; compiler/archiver
failure preserves the previous archive. `--keep-asm` writes a `.delay.s` sidecar; temporary
objects are cleaned up. Ninja and reactos-link track the native source/templates, manifests,
launcher and pinned toolchain. The launcher clears inherited cross-build and jobserver
settings and limits its host Cargo build to one job.

Migration parity against Python at `da29cd4910f`: complete COM output and parsed signatures
for three architectures, RPC C/header fixtures, all three delay-thunk architectures,
compiler-derived ks386 constants, file/time/process CRT prototype pairs, and five real SDK
enum/IOCTL families. Regression fixtures preserve Python bytes, NONAME ordinals, nested
callbacks, arrays and void signatures; integration checks compile real COFF archives for
all three architectures and exercise Ninja invalidation and failed-tool preservation.

## ABI and module generation

Three further commands replace `gen_cnt.py`, `gen_cohab_registry.py`, and
`gen_global_barrier.py`. Their legacy entry points delegate to the binary.

* `cnt [--check] [--output-dir DIR]` parses `cnt-manifest.toml` with the full TOML
  parser and renders the CRT ABI shims, cabi module, and differential symbol metadata.
  It preserves per-function archive granularity, all bespoke shim families, the
  hand-written module imports, and Python's JSON ordering/escaping. The three outputs
  render before any file changes. The default destinations stay inside `--root`;
  `--output-dir` redirects their basenames. No shipping Rust output changed in this port.
* `cohab-registry` prints source-level pairing JSON; `--report` prints only the
  summary to stderr. `--output FILE` writes atomically and `--check` compares against
  that file (default `tools/cohab-registry.json`). This remains an approximation:
  commented CMake entries and Rust hints cannot prove linked symbol coverage.
* `global-barrier` prints the legacy monolithic ntoskrnl barrier. `--source-dir DIR`
  explicitly selects another monolithic crate source tree. `--output FILE` writes
  and `--check` compares against that file (default `global_barrier.rs` in the selected
  source directory). The Python entry point retains its caller-relative checkout
  selection. This does not combine extracted kernel crates: its `crate::...` paths
  cannot address another crate, and their hand-written barriers remain independent.
  The default ntoskrnl source root currently has no committed `global_barrier.rs`;
  no barrier was installed or regenerated by this port.

Both source scanners share a walker that prunes `target`, build, cache, virtualenv,
response, nested-agent checkout and toolchain directories before descent. It never follows directory links,
ignores dangling links, and fails on other traversal/read errors. Basename fallback
for registry Rust references uses that same source-only policy, preventing generated
copies from creating false ambiguity. The native cohab census and its Python snapshot
writer now also prune `.cache`, so cached parity fixtures cannot register as source flips. CMake discovery retains legacy first-hint
precedence; JSON entry/evidence ordering remains canonical.

Parity was checked against Python at `a319085fd99`: all three CRT outputs for the
100-symbol manifest, a separate fixture spanning all 43 slice patterns with new symbol
names, the 342-global barrier text, and complete registry JSON for 1,566 source CMake
files / 1,183 entries. Registry parity feeds both implementations the same pruned CMake
list; build/cache trees intentionally no longer contribute entries. Frozen fixture
hashes cover future-symbol rendering, Unicode JSON, architecture guards, hint resets,
ambiguous basenames, live C references and prose exclusions. The native commands are
explicit selections; `--all` continues to select only the original eleven text outputs.

## Compiler-derived test data

Four commands replace the Python CRT and differential-test generators:

```sh
./vibeos-cli build --arch amd64 --headers-only
./vibeos-cli build --arch i386 --headers-only
tools/codegen msvcrt-consts --check
tools/codegen seh-layout --check
tools/codegen ctype-tables --check
tools/codegen ucrt-cases --arch amd64 --out generated-amd64.inc
```

`msvcrt-consts` compiles the ordered amd64 constant/layout probe and renders three
headers; `seh-layout` compiles the i386 SEH probe and renders one. The shared reader
decodes COFF symbols and section offsets directly, without executing target code or
parsing objdump text. `--recipe-json` inspects the ordered inputs without compiling.
`--output-dir` redirects the headers; `--check` never writes them.

`ctype-tables` shares its parser, renderer and object proof with the native lint rule.
It derives both 257-entry tables from C and the bindgen masks. When the local i386
ctype object exists, every value must match before output is emitted. Its absence
produces an explicit unproven warning; it does not claim object verification.
`--output FILE` replaces only the marked block; the default prints that block.

Compiler tools may be shared, but generated headers, objects and archives must resolve
inside the selected checkout. Headers-only builds prepare the canonical local inputs
under the normal build lock and guards. They are partial builds and invalidate the
boot stamp; they do not produce bootable media.

`ucrt-cases` retains the spec/architecture filters, actual Ninja link inputs, Rust-body
classification, signature restrictions and quarantine. It renders the case include and
`generated-refs.h` together before writing either. Missing reference or Rust archives
fail. `--stats`, `--reverse` and `--ast-json` expose selection and declaration inspection.
Clang AST parsing streams declarations instead of retaining the full JSON tree.
Optional `--cache FILE` keys declarations by the inputs, compiler, headers and active
compiler configuration. Unkeyed caches are regenerated; unsupported external include
or configuration inputs require omitting the cache rather than reusing uncertain data.

Migration validation compared all four probe headers and the ctype block byte for byte
with Python, using local generated headers and the compiled i386 ctype object. UCRT
name/type maps matched on i386 (7,450), amd64 (13,232) and arm64 (6,887 declarations).
Frozen nonempty UCRT fixtures cover selection, quarantine and both generated outputs;
326 real header signatures cover shape classification. Full selection parity against
real UCRT reference/Rust archives remains owed: those archives were absent in the
migration worktree, whose current link graph no longer supplies the old C reference set.
No shipping test headers or Rust tables were regenerated by this port.

## Build recipes and PE layout

`cflags --arch ARCH [--target NAME]` extracts the portable flag template from this
checkout's compile database. It preserves token order, removes PCH/output/generated
include paths, normalizes both the checkout and `/tmp/vibeos` to `{REPO}`, and refuses
inconsistent flag sets. `command` and `arguments` databases are supported. Native
writes require explicit architectures and fail if inputs are absent; `--stdout`
retains the legacy JSON string/null inspection format. The Python entry point keeps
its caller-relative root and default three architectures. The committed-artifact
drift rule now calls the shared Rust function directly.

`baseaddress DIR [-64]` reads PE headers and renders the corresponding file under
`sdk/cmake`. `--output FILE`, `--output-dir DIR`, `--stdout` and `--check` redirect or
inspect it. It retains the module priority/exclusion tables, user32 reservation,
alignment/padding, architecture spacing and four layout variants. Missing-priority
warnings go to stderr. Malformed executables, unknown section layouts and missing
required modules fail before writing. It needs no Python `pefile` package.

Compile-flag JSON matched Python on the local i386 and amd64 databases. Frozen Python
fixtures cover all four base-address variants, a reservation collision and the special
ACM/DRV names. No committed flag templates or base-address assignments changed.
Compiler-dependent tests run live rather than reusing source-only tooling receipts;
`check-tooling --skip-generated` skips the suite requiring local generated headers.

## Payload suite lists

`apitest-suites --arch ARCH` discovers the local build's API-test and unittest binaries
and renders both suite and subtest-skip lists. `--only SUITE[:SUBTEST]` is repeatable;
`--ignore-quarantine` arms quarantined cases while retaining staleness warnings and
marking the list as unsuitable for banking a baseline. Both warnings and the summary
count against the full build before filtering. `--build-dir`, `--out-dir` and
`--quarantine-dir` select explicit inputs/destinations. Unquarantined, sorted discovery
is available through `--discover-json`; it writes nothing and needs either `--arch`
or `--build-dir`. The Windows reference runner uses that native command directly.
The former Python `discover(build_dir)` API is a thin JSON bridge for this checkout.

`winetest-suites --arch ARCH` reads each suite's testlist or standalone `START_TEST`
source, after checking for its local binary. It preserves `--suites`, `--register`,
`--only`, `--skip`, `--repeat`, `--timeout` and `--global-flag` behavior, including
registration order, slow-suite defaults and reproduction annotations. `--out-dir`
selects the destination and its header tag. Both commands support `--check`, render
both files before writing, and reject artifact/source links escaping the selected
checkout. Legacy script entry points and payload build hints continue to delegate.

All fourteen existing quarantine/reproduction regression cases now exercise the Rust
CLI. Seven scenarios additionally compare both files, warnings, summaries and errors
with frozen Python results; negative tests cover invalid options, locality, read-only
discovery and failed generation preserving existing files. No committed payload lists
were changed.

## WoW64 flat thunk generation

`wow64-thunks --spec FILE --sysfuncs FILE --arch ARCH [--out-c FILE]` replaces the
first-stage `wow64gen.py` generator. Without `--out-c`, it prints C. `--manual-list`
accepts comma-separated files; `--symbol-prefix` selects the dispatch table/count
names. `--stats` prints coverage to stderr and `--check --out-c FILE` compares without
writing. Generation preserves the supplied path spellings in provenance comments.

The shared library owns argument kinds, spec filtering, guest service ordering,
classification and C rendering. Missing type information and mismatched dword counts
remain manual stubs. `_WIN64` conditionals are expanded for the i386 guest, retaining
the established treatment of unrelated conditionals. The native lint audit uses that
same source-derived table. The former Python API retains data classes and mutable
object identities through a JSON bridge; stage-two marshalgen callers remain supported.

Both WoW64 CMake commands invoke the native tool directly and track its Rust sources,
templates, manifests, launcher and pinned toolchain. An isolated Ninja fixture checks
cold generation, warm no-op, template invalidation and paths containing spaces.

Migration parity matched complete C output for the real ntdll and win32k recipes on
all three architectures. Frozen recipe inputs and SHA-256 oracles retain that coverage
without coupling tests to future syscall additions. Structured synthetic fixtures and
legacy API tests cover signed pseudo-handle widening, manual reasons, service indices,
duplicate service names and in-place updates. No shipping generated OS C changed.

## Remaining migration work

Outstanding resource refresh, observed 2026-10-18: the committed HAL/i386 and
win32k/i386, amd64, arm64 blobs still encode version 0.4.16. Both Python and Rust
regenerate 0.4.17, differing in four version-metadata bytes per blob (two fixed-version
fields and two UTF-16 digits). Regenerating those four blobs and gating all three
architectures remains owed; this generator port leaves the committed blobs unchanged.

These remain Python implementations; the native generators above do not replace them.

recipe extraction and public Python APIs need a coordinated port with their callers.
