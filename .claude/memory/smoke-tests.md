# Smoke Test Infrastructure

## Overview
QEMU smoke tests (`tests/qemu/test_smoke.py`) are the single source of truth for whether the OS works.
- Boot each arch in QEMU, verify desktop reached, capture screenshot
- 4 tests: boot_and_serial, qmp_status, snapshot_restore, screenshot
- North star boot marker: `explorer.exe created` (i386/amd64), idle detection (ARM64)

## Key Files
- `tests/qemu/vm.py` — VM lifecycle, per-arch ArchConfig subclasses
- `tests/qemu/conftest.py` — session-scoped VM fixture + per-test snapshot restore
- `tests/qemu/test_smoke.py` — the 4 smoke tests
- `tests/qemu/serial_client.py` — Unix socket serial (server-socket pattern, listen before QEMU)
- `tests/qemu/qmp_client.py` — QEMU Machine Protocol (screendump, savevm/loadvm)
- `tests/qemu/debugcon.py` — bochs debug port (0xE9) triage decoder

## Boot Media
- **ARM64**: UEFI ramdisk (`boot.img` + `ramdisk.img`)
- **i386**: LiveCD ISO (`build-i386/livecd.iso`)
- **amd64**: LiveCD ISO (`build-amd64/livecd.iso`)

## QEMU Flags
- i386/amd64: `-accel kvm -cpu host` (KVM acceleration via /dev/kvm in WSL2)
- i386/amd64: `-debugcon file:debugcon.bin` (bochs debug port capture)
- All: `-qmp unix:sock`, `-serial chardev:ser0` (Unix socket serial)
- Scratch qcow2 for savevm/loadvm (i386: `if=none` without device to avoid FreeLDR crash on unpartitioned disk)

## Debugcon Boot Tracing
- Kernel Rust code emits `out 0xe9, al` with single-byte markers at boot milestones
- QEMU captures to file via `-debugcon file:path`
- JSON trace catalogs: `tools/rustconv/data/trace_catalog_{arch}.json`
  - i386: 48 trace points (KiSystemStartup through KiInitializeKernel)
  - amd64: 18 trace points
  - ARM64: no catalog (uses idle detection)
- Catalogs generated by `rustconv trace-catalog` from inline asm patterns in Rust source
- On boot failure, `debugcon.py` decodes raw bytes → triage report showing last milestone reached
